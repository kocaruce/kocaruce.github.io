## 1. 링크 페이지 자체에서 배울 점 (구조와 UX)

참고 가치가 큰 부분입니다. 우리 허브(`index.html` + `js/hub.js`)와 목적이 비슷합니다.

**콘셉트**: "쌩초의 작업 캔버스". 페이지 전체를 디자인 툴 파일처럼 만들었습니다.
- 히어로 영역은 노드 그래프입니다(캐릭터 노드 + Prompt 노드 → Generate 노드). 노드 사이 연결선은 SVG 곡선으로 그리고 순서대로 그려지는 애니메이션을 넣었습니다. Prompt 문구는 CSS Highlight API로 타자 치듯 나타납니다.
- 카테고리마다 색이 하나씩 정해져 있습니다(이미지=하늘, 영상=주황, 디자인=보라, 스킬=노랑, 커뮤니티=연두). 모든 카드가 이 색으로 구분됩니다.
- 링크 타일은 "컴포넌트", 인터뷰는 "코멘트 핀", 탭은 "플로팅 툴바", 푸터는 "상태 표시줄"로 꾸몄습니다. 디자인 툴 메타포를 끝까지 지킵니다.
- `prefers-reduced-motion`이면 인트로 애니메이션을 끕니다.

**콘텐츠 운영 방식: 데이터 파일 하나로 관리**
- 화면은 JS가 그리고, 내용은 배열 4개에서 가져옵니다: `window.NEWS`, `window.VIDEO`, `window.TIPS`, `window.SKILLS`, `window.MAKES`.
- 항목 하나의 필드: `{ id, title, desc, tag, url, thumb, new }`
  - `id`로 짧은 주소가 생깁니다(`/tip7`, `/skill3`, `/make2`. `#tip7`, `?t=tip7`도 됨). 해당 카드로 스크롤하고 강조합니다.
  - `tag`가 색과 아이콘을 정합니다(정해진 매핑이 없으면 기본값).
  - `new: true`면 NEW 배지가 붙습니다. `url`이 비어 있으면 "링크 준비 중"이 표시됩니다.
- 같은 태그끼리 묶어 보여주고, 10개마다 페이지를 나눕니다.
- 파일 맨 위에 "새 팁을 올릴 때는 이 파일만 고치면 됩니다"라는 운영 안내 주석이 있습니다. 비개발자인 본인이 직접 유지보수할 수 있게 만든 구조입니다.

**버튼 동작**
- 스킬 카드에는 "열기" 대신 **[스킬 링크 복사]** 버튼이 있습니다. 누르면 "복사됨! Claude/GPT에 붙여넣기"로 바뀌고, 클립보드가 막히면 주소를 선택 가능한 텍스트로 보여줍니다.
- 모든 카드에 [공유] 버튼이 있어 짧은 주소를 복사합니다.
- 스킬 탭 맨 위에는 "README · 스킬 설치 방법" 3단계가 붙어 있습니다: ① 링크 복사 후 "이 스킬 설치해줘" ② 안 되면 ZIP 업로드 ③ 말로 실행.
- 메일 링크는 데스크톱이면 Gmail 쓰기 창, 휴대폰이면 기본 메일 앱으로 엽니다.
- 유튜브는 실제 사이트에서는 iframe(nocookie)으로, 미리보기 환경에서는 링크로 보여줍니다.

**우리에게 적용할 점**
- 놀이 도구와 가이드가 늘어나면 `hub.js`도 **데이터 배열 + 렌더 함수** 구조로 바꾸고 `#play-3` 같은 짧은 주소를 지원하면 선생님들이 공유하기 편해집니다.
- 카테고리 색 체계를 우리 `css/tokens.css` 토큰과 연결합니다.

### tip1. AI 디자인 필수 사이트 모음 (디자인)

- **기본 프로세스**: 기획(챗GPT·제미나이) → 레퍼런스(핀터레스트·비핸스) → 초안(미드저니=미학, 나노바나나=프롬프트 인식률) → 수정·베리에이션(나노바나나, 씨드림) → 필요하면 4K 업스케일(매그니픽, 토파즈 등) → 세부 편집(포토샵) → 디자인 마무리(피그마) → 이미지→영상(클링·베오·소라·하일루오) → 사운드(픽사베이·아트리스트·SUNO) → 편집(짧은 영상은 어도비 익스프레스, 긴 영상은 캡컷).

**참고 포인트**: 툴 목록에서 끝내지 않고 **"어느 단계에 무엇을"**로 정리한 점. 선생님용 "수업 자료 만들기 툴 지도"를 만들 때 그대로 쓸 수 있는 형식입니다.

### tip2. AI로 만든 디자인, 인쇄까지 실패 없이 하는 법 (디자인)
**흐름**: 문제 제기 → 나쁜 예/좋은 예 → 인쇄 3요소 → 한계와 다음 단계.

- 한 줄 프롬프트("멋진 국밥집 포스터")의 문제: 글자 깨짐, 화질 저하, 색 틀어짐, **AI 티로 인한 브랜드 신뢰 하락**(가장 심각하다고 강조).
- 좋은 프롬프트의 구조(국밥집 예시): `주제 한 줄` → `배경(HEX)` → `분위기` → `색상(HEX)` → `조명` → `구도` → `연기·질감` → `폰트(위치, 방향, 문구)` → `상호·장식` → `연출(실사처럼 자연스럽게)` → `[가이드]` 문단 → `[피해야 할 요소]` 목록.
- 핵심 3가지: 거부감 없는 연출 지시, 여백과 구도를 미리 잡기, 인쇄 사양 지키기. 그리고 **레퍼런스는 참고만**(그대로 베끼면 도용).
- 인쇄 실전
  1. **해상도**: 실제 mm 크기, 최소 150~300dpi. 업스케일 툴(힉스필드·매그니픽·캔바)은 "적당한 품질"까지만 됩니다. 정확한 크기와 300dpi는 디자인 프로그램에서 맞춰야 합니다.
  2. **컬러**: RGB→CMYK(포토샵·일러스트 컬러 모드, rgb2cmyk.org). 바꾼 뒤 칙칙해지면 색 보정.
  3. **폰트 저작권**: AI가 만든 글자는 저작권이 불분명합니다. 산돌구름(한글)과 어도비 폰트(영문)로 자동 스캔하고, 유료 폰트로 나오면 교체합니다. 처음부터 저작권 프리 폰트를 지정하는 것이 가장 안전합니다.
- 결론: AI 이미지는 "디자인 파일"이 아니어서 세밀한 조정이 어렵고 수정할수록 흐려집니다. 포토샵·일러스트·피그마를 함께 쓰는 쪽이 빠릅니다.

**참고 포인트**: 우리 놀이 도구의 **인쇄용 학습지·간판·스티커** 기능을 만들 때 체크리스트(300dpi, CMYK 안내, 무료 폰트만)로 씁니다.

### tip3. 머릿속 상상을 영상으로 만들기 (영상)
**5단계**: ① 상상을 한 문장으로(어디서/누가/무슨 일) ② AI와 수다 떨며 이야기 늘리기("확장해줘", "10초에 담으려면?", "더 재밌게?") ③ **주인공 얼굴 고정 = 캐릭터 시트**(3열×2행, 표정 2종 × 정면/반측면/측면) ④ 영상 뽑기 ⑤ 첫 줄이 중요한 SNS 문구로 올리기.

- 사이트 비교표: Higgsfield(가장 많이 씀, 초보용) / 빠나나ai(품질) / kie.ai(저렴) / ChatGPT(기획). 사용자 유형별 추천 조합도 있습니다.
- **프롬프트를 대신 써 달라는 메타 프롬프트**: 캐릭터(시트 참조) / 배경 / 일어나는 일(한 문장에 하나) / 카메라(샷 사이즈·앵글) / 소리(배경음·효과음·감탄사) 다섯 항목 필수. 조건은 한국어, 10초 분량, 간결하게, 금지 사항은 "~는 절대 없다", 대사 대신 의성어.
- 설정 추천: 9:16, 10초, 720p.
- 다시 뽑을 때 쓰는 고치기 원칙 3가지: **숫자로 못 박기**("정확히 세 개"), **화면 밖으로 넘기기**(잘려야 커 보임), **하지 말 것도 적기**.
- "소리를 꼭 넣으세요. 컷편집할 거면 BGM은 빼고 생성."

**참고 포인트**: 아이들 대상 "상상 → 영상" 놀이 가이드의 단계 구성, "문제 | 해결" 표 형식.

### tip4. AI 디자인할 때 원하는 폰트 그대로 넣기 (이미지)
- BEFORE(폰트 지정 없음, AI 티)와 AFTER(디자이너가 고른 듯한 서체)를 비교하며 시작합니다.
- **방법 1: 분위기 묘사.** 실제 넣을 문구를 원하는 폰트로 타이핑하고 확대(Ctrl +)해서 캡처합니다(한 장에 폰트 하나, 헤드라인과 카피는 따로). 이 견본을 Claude에게 주고 **획 / 자형 비율 / 자간·정렬 / 질감 / 전체 인상** 5항목으로 묘사하게 합니다. 마지막에 영문 프롬프트 한 문단으로 압축하게 하고, **"폰트 이름은 추측하지 말 것"**을 꼭 넣습니다(넣지 않으면 AI가 엉뚱한 폰트 이름을 지어내고 그 폰트를 그립니다).
- **방법 2: 정확히 지정.** 눈누(한글), DaFont 100% Free(영문)에서 고르고 캡처본을 첨부합니다. 프롬프트에 `[첨부 폰트 자료] 이미지1=헤드라인, 이미지2=서브카피, 섞지 말 것`처럼 **폰트 명령을 항목별로 분리**합니다.
- 포스터 프롬프트 구조: `비율·주제` → `[배경 이미지]` → `[헤드라인] 문구/서체/색/위치` → `[서브 카피] …` → `[규칙]`.
- ❌/✅ 변환표: "카페24 단정해체로" → "획 굵기가 일정하고 끝이 둥근, 어린이 글씨 같은 한글 서체"처럼 이름 대신 형태로 씁니다. 기준은 하나입니다. **"이 폰트를 본 적 없는 사람이 읽고 따라 그릴 수 있는가."**
- 문제 해결: 한글이 깨지면 문구를 줄이고, 글자를 키우고, 그래도 안 되면 글자는 피그마·포토샵에서 직접 얹습니다. 시리즈물은 같은 묘사문을 재사용하고 첫 장을 레퍼런스로 줍니다.

**참고 포인트**: 우리 손글씨 간판(`assets/aurora-sign.png`)처럼 **아이들 손글씨를 디자인에 넣는 놀이**에 바로 쓸 수 있습니다. 묘사 5항목은 "글자 관찰하기" 활동지로도 바꿀 수 있습니다.

### tip5. GPT ASTRA로 모션그래픽 만들기 (영상)
**흐름**: 코덱스 다운로드 → 레퍼런스·음악 분석 → 제작 → 수정 → 저장 (10단계).
1. ChatGPT 데스크톱 설치 → 2. Codex 선택 → 3. 프로젝트에 로컬 폴더 연결(`music / fonts / images / videos`로 나눠 두기. 매번 첨부할 필요가 없고 결과물도 같은 폴더에 저장됨) → 4. 모델 ASTRA 선택(가벼운 작업은 Light부터, 복잡해지면 사고 강도를 한 단계씩 올림) → 5. 레퍼런스 영상 분석(색감·타이포·구성·전환·흐름. **"아무 영상이나 알아서 참고"는 금지**, 저작권 문제) → 6. 음악 준비(Suno, Pixabay, 내 파일, 생략 가능) → 7. 제작 프롬프트(주제·필수 내용·음악 파일·비트 싱크·길이·비율·컬러·폰트 위계·문구·소스 경로·저장 위치를 [대괄호] 템플릿으로) → 8. **초 단위 수정**("2~3초 제목을 더 크게, 위에서 떨어지게, 마지막 로고 1초 이상 유지") → 9. MP4와 편집 프로젝트 ZIP 보관 → 10. **"지금까지 대화를 바탕으로 다음에도 이 스타일을 쉽게 만들 수 있는 스킬 파일을 만들어줘"**(본인 측정: 30분 작업이 5분으로 줄었다고 함).
- 샘플·튜토리얼 유튜브 4개: e4AOBY_qTaw, n3u_jppsbKA, 78EO-35ofyo, rRCOfj-_-uE.

**참고 포인트**: "작업이 마음에 들면 대화를 스킬로 굳히기". 우리도 놀이 도구를 하나 만들 때마다 같은 방식으로 `.claude/skills/`에 제작 스킬을 쌓아 갈 수 있습니다.

### tip5 하위. 3D 툴 안 켜고 3D 하기 · 입체 타이포 영상 (영상)
- 결과물: 통통한 풍선 글자(광택, 가장자리 주름) + 작은 캐릭터·꽃 장식. 요소마다 시차를 두고 등장한 뒤 둥둥 떠 있습니다.
- 흐름: 자료 준비 → **정지 시안 → 저해상도 모션 시안** → 수정 → 음악·효과음 → 최종(MP4 + .blend).
- 준비물: 정확한 문구(대소문자·줄바꿈), 규격(9:16, 1080×1920, 8초), 분위기, 레퍼런스, 폰트 파일(OTF/TTF), 음악.
- **요소별 레퍼런스 역할 지정표**: 글자 형태 / 재질 / 배치 / 캐릭터 / 배경 / 조명 / 움직임(영상의 n~m초). 규칙: "레퍼런스의 문구는 사용하지 마", "충돌하면 내 지시 우선", "제작 전에 각 자료에서 쓸 특징을 먼저 정리해 줘".
- 폰트는 정확한 이름과 굵기, 실제 파일, 언어별 폰트, 줄바꿈·자간·행간, 부풀려도 유지할 속공간(O, A, R). "폰트를 불러올 수 없으면 임의로 바꾸지 말고 알려줘."
- 모션 시간표 예: 0~2초 시차 등장(약한 탄성) / 2~6초 요소마다 다른 주기·작은 진폭의 부유 / 6~8초 읽히도록 유지.
- 수정은 **"유지할 것 먼저 → 무엇을, 얼마나, 어떻게"** 순서. 대상별 예시 표(형태, 주름, 광택, 가독성, 등장, 부유, 마지막 장면)가 있습니다.
- 음원은 상업적 무료 조건이 확인된 것만 쓰고, 출처와 크레딧 조건을 목록으로 받습니다.
- 마지막 체크리스트 5개.

### tip6. 영상 속 동작 그대로, 배경·인물 바꾸고 VFX 추가 (영상)
- 툴: GPT(유튜브 앞 15초 저장), Kling 4.0(인물·배경 교체, 음악 포함), Claude(VFX, 가사 타이포, 비교 영상).
- Kling 단계 팁: 안무·카메라·컷은 원본 뮤비에 이미 있으니 따로 설명하지 않습니다. **자막은 이 단계에서 넣지 않고**, **배경은 어둡게** 합니다(네온이 살고 인물 분리가 쉬움).
- Claude VFX: 레퍼런스 톤으로 약하게 색 보정, 인물 자동 분리, 비트·킥 분석. 효과는 몸에서 피어오르는 네온 에너지, 잔상, 전기, 킥마다 충격파와 펀치 줌, 인물 주위를 도는 라인 광선(뒤를 지날 때는 가려짐). **절대 규칙: 얼굴과 동작이 항상 보이고, 하얗게 날리거나 깜빡이지 않을 것.** 진행은 480p 미리보기 → 720p 최종(렌더 시간 480p 약 6분, 720p 8~10분, 1080p 15~20분).
- 가사 타이포: Bebas Neue, 시안 네온 글로우, 단어별 모션블러 슬라이드, 킥에 글리치. **가사와 초 단위 타이밍을 직접 적어 줍니다.** 목록에 없는 글자와 구두점은 금지, 얼굴은 피해서 배치.
- 수정은 구간 단위로 요청합니다("13~15초만 다시, 전체 재렌더 금지").
- 비교 영상: 위는 VFX, 아래는 원본. 알약 라벨, 간격 18px.

### tip7. 초보자를 위한 온라인 전시관 만들기 (바이브코딩)
**4단계**: 자료 준비 → 만들기 요청 → 확인·수정 → 링크 공유. 팁 10개:
1. 닉네임별 폴더로 자료 정리, 파일명에 작품 제목
2. 영상 원본은 따로 보관하고 재생용 사본 만들기
3. **처음부터 전부 넣지 않기**: 작품 3개로 입장과 재생부터 확인
4. 말 대신 캡처에 동그라미·화살표로 표시해서 요청하고, 유지할 것도 함께 말하기
5. 앞뒤 줄을 엇갈리게 배치하고 이름표는 작품 위에
6. 사진 때문에 전시장을 무조건 넓히지 말고 "선택 작품만 보기"
7. 보는 각도와 사진 저장을 구분(정면 전환은 별도 버튼, 저장은 현재 각도 그대로, UI는 빼고)
8. 프로필 사진과 맵 캐릭터는 따로 정하기
9. 휴대폰에서 직접 써보기(두 손가락 확대, 입력칸을 누를 때만 키보드, 다른 앱에서 돌아와도 상태 유지)
10. **미리보기와 최종 공유 링크는 다를 수 있으니 실제 링크로 확인**
- 기본 요청문: 받침대 위 작품, 닉네임 입력 후 캐릭터 선택 입장, 작품을 누르면 확대·재생, 포토존, 모바일 대응, 미리보기 후 공유 링크, "비용이 생기면 진행 전에 알려줘".
- 공유 전 체크리스트 3개. "다운로드 버튼을 숨겨도 저장·녹화를 완전히 막을 수는 없다"는 주의도 있습니다.

**참고 포인트**: 우리 **"우리 반 작품 전시회"** 놀이를 만들 때 요구사항 목록으로 그대로 쓸 수 있습니다. 팁 3, 9, 10은 우리 개발 원칙과도 같습니다.

### 공통 작성 패턴 (우리 스킬에 그대로 쓸 것)
1. **frontmatter의 description에 실제 발화 예시를 많이 넣습니다.** 예: "이 이미지를 폰트로 만들어줘", "O만 다시". 트리거를 넓히는 방식입니다.
2. **"절대 규칙", "절대 금지"를 따로 묶습니다.** 대부분 실제 수정 요청에서 나온 규칙이고, 문서에 그렇다고 밝혀 둡니다("아래 규칙은 실제 수정 요청을 모은 것이니 하나도 빼먹지 않는다").
3. **만들기 전에 묻습니다.** 질문은 한 번에, **객관식**(번호 + A/B/C, 추천 표시, "알아서" 보기, "1A 2B처럼 답해 주세요")으로. 이미 정해진 것은 다시 묻지 않습니다.
4. **본 렌더 전에 시안을 먼저 보여줍니다.** 정지 화면 → 확정 → 렌더. 수정할 때는 바뀐 구간만 다시 렌더해서 이어 붙입니다.
5. **모든 그림을 시간 t의 함수로 그립니다.** 어느 지점으로 이동해도 같은 화면이 나오고, Playwright로 프레임 단위 렌더가 됩니다. CSS transition에 기대지 않습니다.
6. **결과를 줄 때 "내가 정한 것, 추정한 것, 뺀 것"을 함께 알립니다.** 못 본 것을 봤다고 하지 않고, 확인이 안 되면 스크린샷을 요청합니다.
7. **폰트·음원 라이선스 원칙**: 상업 무료만, CC0 우선, 나눔손글씨 계열은 금지(가늘어서 안 읽힘).
8. **모바일 함정을 문서화합니다.** 아티팩트에 커넥터(capabilities)를 선언하지 않기, 오디오와 영상을 따로 재생하지 않기, 첫 프레임이 갈색으로 보이는 문제, 인스타 UI 영역(y 1540 아래) 비우기.

### skill1. stopmotion-collage-edit (스톱모션 콜라주 편집)
- **확정할 4가지**: 주제(객관식), 컬러 팔레트(파스텔 3~4색 + 잉크색, HEX), 음악(필수, 가사 포함), 영문/한글 위주. 원본 비율(9:16 크롭 / 원본 그대로)도 묻습니다. 폰트는 묻지 않고 기본값(영문 Homemade Apple + Abril Fatface, 한글 Gamja Flower/Gaegu + Black Han Sans/Song Myung).
- **분석**: ffprobe, 장면 전환 검출 `select='gt(scene,0.3)'`, librosa 비트, faster-whisper 단어 타이밍. 길이는 음악에 맞추고, 씬마다 주요 피사체 위치를 기록합니다.
- **스타일 수치**: 12fps 스텝, 낙서 떨림 6Hz, 영상은 324×576 버퍼, 글자층은 540×960에 그린 뒤 잉크를 깎아냄, 종이 질감 multiply 0.7, 채도 약 1.1 + 따뜻한 막 7%, 0.25초마다 흔들림 ±9px·±0.4°, 겉 프레임 5종을 1~1.5초마다 교체.
- **절대 금지**: 드롭섀도·글로우·안개, 단색 배경(PPT처럼 보임), 박자 줌, 밝기 깜빡임, 같은 배치 반복 등.
- 씬 구성 공식(오린 단어 조각, 손글씨 한 단어, 낙서, 폴라로이드, 사진 카드 씬), 엔딩 공식(이름 + 주제와 이어지는 마무리 말 + 회전 글자 띠, 페이드아웃 없음).
- 구현 뼈대 JS(`rng`, `tornRect`, `wob`, `pen`, `frameMode`, `paperFrame`, `drawFrame`)와 출고 전 점검표 9개.

### skill2. painterly-animation (회화 애니메이션)
- AI 생성 도구 없이 **three.js 0.160 단일 index.html**로 그립니다. 원작 디자인 복제 금지, 캐릭터는 오리지널.
- 기법: Canvas2D 시드 랜덤 붓터치(덤불, 도형, 구름, 숲, 꽃, 덩굴), 직교 카메라 + 시차 레이어, 버텍스 셰이더 바람, fbm 물결과 반사, 후처리(쿠와하라 반경 3 + 종이결 + 따뜻한 그레이드).
- 연출: `SHOTS=[시작,끝,장면,x0,y0,x1,y1,줌0,줌1,롤0,롤1]`. 샷 종류를 섞고, 흰 플래시 전환과 눈 극단 클로즈업은 금지("무섭다"는 피드백).
- 작업 순서: 컷별 스틸 한 장 시안 → Playwright `window.renderAt(t)` + node 4개 병렬 렌더 → ffmpeg. 수정은 바뀐 컷만.
- 소리는 CC0 저장소에서 고르고 ffmpeg adelay/amix로 믹스. 자막은 고운바탕 흰색, 12자 안팎, 2초 이상. 실존 장소면 역사를 검색해 출처와 함께 문구 후보를 냅니다.

### skill3. zoom-in-screen (화면 녹화 줌 편집)
- **확대하는 경우**: 중요한 버튼 클릭, 프롬프트 입력(창 전체), 팝업(가운데로), 사용자가 지정한 구간. **확대하지 않는 경우**: 오프닝, 빈 공간, 커서가 떠도는 장면, 전체 화면을 보여줘야 할 때, 화면 전환 직후 약 3초, 모션그래픽.
- 배율은 기본 2배(맥락이 중요하면 1.5배, 입력창은 자막과 겹치지 않게 2배). 같은 입력창이면 확대를 계속 유지하고, 간격이 2.5초 미만이면 바로 이어서 이동. **카메라 고정**(커서를 따라가지 않음), 들어가고 나올 때만 약 0.6초 이징.
- 빨간 라운드 박스(5px, 반경 14px 이하)는 **화면을 실제로 바꾼 클릭에만** 넣습니다. 클릭 후보마다 t−0.3초와 t+0.6초 프레임을 직접 보고 확인합니다.
- 파이프라인: `detect_cursor.py`(색으로 커서 검출) → `plan_zoom.py`(구간 자동 계산, `manual.json`으로 덮어쓰기, `--exclude`) → 클릭 검증 → `render_zoom.py` 전후 비교 스틸 → `splice_render.py`(효과 구간만 재인코딩, 나머지는 `-c copy`, 오디오 원본 유지). 스크립트 4개는 저장소에 없고, SKILL.md 설명대로 그때그때 만들게 되어 있습니다.
- 전달: 효과 구간만 모은 확인용 영상 → 앞부분/뒷부분으로 나눠 확정.

### skill4. video-storyboard (영상 스토리보드 편집기)
- 설정 폼은 만들지 않습니다. 재료는 채팅으로 받고, 컬러·폰트(2~3안)·레퍼런스·글자 언어를 한 번에 제안합니다. 주제 한 줄만 있어도 바로 제안합니다.
- **HTML 아티팩트 한 장**: 왼쪽 플레이어(재생/일시정지, 처음부터, 화면 탭 토글, 스페이스바, 씬만 재생, 반복, 박자 눈금 타임라인) + 오른쪽 카드(전체 설정 + 씬 카드: 화면/글자/움직임/소리 4줄 + 수정사항 칸).
- **적용 버튼**은 수정사항을 `[전체] …`, `[씬 2 2.4–4.9초] …` 형식으로 클립보드에 복사하고, 사용자가 채팅에 붙여 넣습니다. 커넥터로 직접 보내는 방식은 모바일에서 깨져서 쓰지 않습니다. 입력은 localStorage에 저장합니다(try/catch).
- 데이터는 `SC`(씬 카드)와 `EL`(요소) 두 배열로 나누고, 수정할 때는 이 둘만 바꿔 **같은 URL로 다시 게시**하고 버전을 올립니다(v2, v3…).
- 영상과 음악이 둘 다 있으면 미리 하나로 합쳐 video 하나만 재생합니다(모바일 오디오 싱크 문제).
- 수정 반복 원칙: 말한 씬만 고칩니다. 애매하면 그럴듯하게 고치고 "이렇게 읽었어요"라고 알립니다. 안 된다고 하지 않습니다.

### skill5. image-to-fonts (이미지로 폰트 만들기)
- 단계: 0) **폰트 이름부터 묻기**(영문 권장. 한글 이름은 포토샵 목록에 투명하게 뜸) → 1) 해상도 확인(글자 높이 300px 이상 권장. "울퉁불퉁"하다는 피드백의 90%는 해상도 문제) → 2) 분해(`img2bin.py` → `pipeline.js segment`. 26/52/62개면 자동 라벨, 아니면 contact sheet를 눈으로 보고 라벨링) → 3) 빌드와 QA(윤곽 닫힘 검사, fontbakery FAIL 0, OTS PASS, 미리보기 렌더) → 4) 전달(.otf + project.json + zip + 미리보기 HTML. 아티팩트 `{downloads: true}` 선언) → 마지막에 수정할 글자나 자간이 있는지 반드시 묻기.
- `patch` 명령으로 글자 하나만 고해상도 이미지로 교체(이미지 전체 잉크를 글자 하나로 취급), 자간·커닝·오버슈트 상수 조정.
- 엔지니어링 메모: UPM 1000 / ascender 760 / descender −240(합 1000), 대문자 높이 700 정규화, 반올림 계단 현상 2차 단순화, CFF 좌표를 정수로 넘기기(시작점 가시 버그 수정).
- "실제로 있었던 심각한 버그"와 "스킬 로직에 넣지 말라고 지시받은 일회성 요청"을 따로 기록해 둔 점이 좋습니다. 같은 실수를 반복하지 않게 하는 장치입니다.
- 예시 폰트: `examples/sc-daisy.otf`, `sc-daisy_preview.html`.

## 5. 우리 제작에 바로 쓸 체크리스트

**가이드 문서 (`guides/*.html`)를 쓸 때**
- [ ] 맨 위에 "누가, 왜 만들었는지" + 소요 시간 + 준비물
- [ ] BEFORE/AFTER 또는 나쁜 예/좋은 예로 시작
- [ ] 단계에 번호를 붙이고, 각 단계에 "복사해서 쓰는 문장"을 코드 블록으로
- [ ] [대괄호] 자리 표시가 있는 템플릿
- [ ] "문제 | 해결" 표, ❌/✅ 변환표
- [ ] 끝에 요약(5단계 요약)과 체크리스트
- [ ] 저작권·출처 안내를 한 줄로, 커뮤니티 링크는 하단에

**프롬프트를 쓸 때**
- [ ] 항목별 블록: `[배경] [헤드라인] [서브 카피] [규칙] [피해야 할 요소] [진행]`

- [ ] 레퍼런스는 자료마다 역할을 지정하고, 충돌하면 내 지시를 우선
- [ ] 시안을 먼저(정지 → 저해상도 → 최종), 수정은 시간 구간 단위
- [ ] 결과가 좋으면 "이 대화를 스킬 파일로 만들어 줘"

## 부록. 조사 방법과 한계
- 링크 페이지 HTML에 들어 있는 데이터 배열(`window.TIPS/SKILLS/MAKES/NEWS/VIDEO`)에서 전체 목록을 뽑았습니다. 화면에 보이는 개수와 같습니다(팁 7, 스킬 5, Lab 6).
- 노션 페이지는 공개 페이지 API로 블록 전체를 받아 텍스트로 바꿨습니다. 이미지(스크린샷, 결과 예시)는 내용을 보지 않았고 위치만 확인했습니다. 팁 1의 "위비(Weavy)" 항목은 다른 블록을 참조하는 블록이라 링크 주소를 확인하지 못했습니다.
- 스킬은 GitHub 저장소 main 브랜치의 최신 커밋(`0bb01d2`, image-to-fonts 추가)을 읽었습니다.
- Lab 사이트는 첫 화면 HTML과 공개 JS 데이터만 확인했습니다. 로그인이나 API가 필요한 동적 내용(랭킹, 접속자)은 확인하지 않았습니다.
- 모든 내용은 2026-11-21 기준이고, 원작자가 계속 업데이트합니다(팁 1: "지속적으로 업데이트됩니다").
